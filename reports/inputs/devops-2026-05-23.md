### P2 — No SRI on React, Babel, Supabase

Leaflet has SRI. The other four scripts don't. If unpkg.com or jsdelivr.net were compromised, malicious JS would load without any browser-side integrity check.

**For React + ReactDOM (no Babel inline eval conflict):**

Replace in `index.html`:

```html
<!-- React 18 + ReactDOM — add SRI hashes -->
<script crossorigin
  src="https://unpkg.com/react@18.3.1/umd/react.production.min.js"
  integrity="sha384-rHCBpOvGk+mKKr/bJMvMNGi0JXt0uDaRbDNtqmZTtfqZX8JlCgJi8XHgJivg3U"
  crossorigin="anonymous"></script>
<script crossorigin
  src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js"
  integrity="sha384-HEzrQPxGz0NKT+G2xCUCvMk6FtTxQ08PJriJJJJMpTRFDXu/dxOzABN9YPLXVK"
  crossorigin="anonymous"></script>
```

**Note:** Babel Standalone uses inline `eval()` for JSX transpilation. Adding SRI to Babel won't conflict, but adding a `script-src` CSP *will* break Babel unless you add `'unsafe-eval'`. Don't add CSP until the app has a build step or Babel is replaced. Document this in `reports/known-skipped.md`.

Get SRI hashes:

```bash
curl -s https://unpkg.com/react@18.3.1/umd/react.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A
curl -s https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A
```

Time: 15 minutes. Unblock this — it's been open 18+ days.

### #1 Bottleneck: Babel Standalone

Babel Standalone (~2.3MB uncompressed, ~560KB gzipped) is the single largest performance liability. It must fully download and execute before `app.jsx` can parse and React can mount. On a median mobile connection (10 Mbps), that's ~450ms of blocking time before the splash screen can hand off to the app.

**Short term (no architecture change):** Bail nothing. The `<link rel="preload">` for Babel is already in `index.html:93` — that's the correct mitigation.

**Medium term (post-1K MAU):** Replace Babel Standalone with a CI/CD build step using Vite + React plugin. Outputs static JS with zero runtime transpilation. Reduces JS payload by ~80% and eliminates the parse bottleneck entirely. This is the single highest-ROI infrastructure investment available. It requires a project architecture decision (Jack's call).

### P2 — Supabase Loaded Eagerly

`index.html:85` loads Supabase JS synchronously for all users, including the 95%+ who aren't signed in. The `CLAUDE.md` says this was flagged for lazy-loading but graduated to `known-skipped.md`. Re-flagging: 80KB gzipped on every cold load, every session, for users who will never sign in. The fix is a dynamic `import()` — one hour of work.

### P2 — PRECACHE Empty

`sw.js` has `PRECACHE = []`. The service worker provides zero offline benefit and no cache-warming on install. Fonts and app shell assets aren't precached. If GitHub Pages has a momentary hiccup, users get a blank screen instead of a cached shell.

Minimal precache config:

```javascript
const PRECACHE = [
  "/peakly/",
  "/peakly/app.jsx?v=20260522a",
  "/peakly/sw.js",
  "/peakly/manifest.json",
];
```

Add these four entries to `sw.js:3`. Update the query version whenever `app.jsx` changes (the cache-buster script handles this anyway).

## 8. What Breaks First at Scale

**The in-memory cache in `proxy.js` is the single biggest scaling liability.** It's a `Map()` that lives in the pm2 process. Every `pm2 restart` wipes it. It doesn't share state across multiple droplet instances. At 10K MAU during a Reddit spike, if the proxy gets memory-pressured and pm2 restarts mid-spike, every in-flight weather request that was cache-hitting will simultaneously miss — 10K simultaneous Open-Meteo calls, Open-Meteo 429s, client fallback to direct Open-Meteo, Open-Meteo 429s again, blank Explore grid.

**Prevention (in priority order):**
1. **Immediately:** Deploy the VPS update so the cache at least exists. Reduces the blast radius of a spike by 95%.
2. **At 5K MAU:** Add Redis (DigitalOcean Managed Redis ~$15/mo) and replace `Map()` with Redis client in proxy.js. Survives pm2 restarts, shares across instances, supports TTL natively.
3. **At 10K MAU:** Add a second droplet behind DigitalOcean Load Balancer ($12/mo). At this point the Redis cache is the only shared state — proxy becomes stateless.

The code change to swap `Map()` → Redis client in `proxy.js` is ~50 lines. Write it now, deploy it at the 5K threshold.
