### Structural Note: Agent Queue Stales the Buster Every Day

DevOps runs at 14:00; Content runs at 15:00. DevOps bumps the buster; Content edits `app.jsx` an hour later. Result: buster is stale by 15:xx every day Content ships code. This has caused a P0 on multiple consecutive runs. The fix (from 2026-05-26 report, still not applied):

```bash
# Add to scripts/auto-push.sh, after dirty-check, before git add:
TODAY=$(date +%Y%m%d)
CURRENT=$(grep -o 'PEAKLY_BUILD = "[0-9a-z]*"' app.jsx | grep -o '"[0-9a-z]*"' | tr -d '"')
if [[ "$CURRENT" != "${TODAY}a" && "$CURRENT" < "${TODAY}" ]]; then
  sed -i "s/PEAKLY_BUILD = \"[^\"]*\"/PEAKLY_BUILD = \"${TODAY}a\"/" app.jsx
  sed -i "s/CACHE_NAME = \"peakly-[^\"]*\"/CACHE_NAME = \"peakly-${TODAY}a\"/" sw.js
  sed -i "s/app\.jsx?v=[0-9a-z]*/app.jsx?v=${TODAY}a/" index.html
fi
```
10-minute add. Eliminates this entire class of P0 permanently.

### P2-A — Missing SRI on 4 CDN Scripts

Leaflet already has SRI (✅). These 4 do not:

```
https://unpkg.com/react@18.3.1/umd/react.production.min.js
https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js
https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.106.2/dist/umd/supabase.min.js
https://unpkg.com/@babel/standalone@7.29.7/babel.min.js
```

**Get the hashes (run locally):**
```bash
curl -s https://unpkg.com/react@18.3.1/umd/react.production.min.js | openssl dgst -sha384 -binary | base64
curl -s https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js | openssl dgst -sha384 -binary | base64
curl -s "https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.106.2/dist/umd/supabase.min.js" | openssl dgst -sha384 -binary | base64
curl -s https://unpkg.com/@babel/standalone@7.29.7/babel.min.js | openssl dgst -sha384 -binary | base64
```

Then add `integrity="sha384-<hash>"` to each script tag. **Caveat:** Babel uses `eval()` internally for JSX transpilation. A CSP with `script-src` that blocks `unsafe-eval` will break JSX rendering — test in browser before shipping. SRI alone (no CSP) adds supply-chain protection without that risk.

**Single largest bottleneck: Babel Standalone (~340 KB gzip).** It's the JSX transpiler. On a mid-range Android (Moto G), this adds ~1–2s to TTI on first load. This is a known architectural trade-off (no build step) — acceptable until 10K MAU at which point a Vite build step would shave ~500ms off cold load. Do not change this now.

**P2-C — Supabase eagerly loaded despite lazy-init logic in app.jsx:**
The `<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.106.2/dist/umd/supabase.min.js">` in `index.html:85` loads synchronously on every page load (~80 KB gzip), even for the ~85% of users who never sign in. The lazy-init guard in `app.jsx` (`_initSupabase()` only runs on sign-in / magic-link callback) means the JS is parsed and idle for most users. A `reports/ready-to-ship/eager-supabase-delete-2026-05-08.diff` exists and is `git apply`-clean — move Supabase to a dynamic `import()` shim. Still graduated to `known-skipped.md` per two-strikes rule; re-escalating here because TTI compounds with Babel cost on low-end devices.
