### P1 — No SRI on React, ReactDOM, Supabase, Babel (Day 20, Unresolved)

Leaflet has `integrity=` hashes. The four largest scripts do not. A compromised unpkg or jsdelivr CDN serves arbitrary JS into every session before Sentry fires.

**Generate + apply hashes (run from any machine with curl + openssl):**
```bash
REACT_HASH=$(curl -s https://unpkg.com/react@18.3.1/umd/react.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A)
DOM_HASH=$(curl -s https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A)
BABEL_HASH=$(curl -s https://unpkg.com/@babel/standalone@7.24.7/babel.min.js | openssl dgst -sha384 -binary | openssl base64 -A)
SUPA_HASH=$(curl -s https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2.45.4/dist/umd/supabase.min.js | openssl dgst -sha384 -binary | openssl base64 -A)
echo "React:    sha384-$REACT_HASH"
echo "ReactDOM: sha384-$DOM_HASH"
echo "Babel:    sha384-$BABEL_HASH"
echo "Supabase: sha384-$SUPA_HASH"
```

Then add `integrity="sha384-<value>" crossorigin="anonymous"` to each `<script>` tag in index.html. Test in browser immediately — SRI blocks load if the CDN serves different bytes. **Time: 20 min.**

### P2 — No Content Security Policy (Day 20, Unresolved)

GitHub Pages can't set HTTP headers; meta tag only. Babel requires `'unsafe-eval'` which limits scope, but blocking unknown `connect-src` origins still matters.

**Add to `<head>` in index.html before the Sentry script:**
```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self';
  script-src 'self' 'unsafe-eval'
    https://unpkg.com
    https://cdn.jsdelivr.net
    https://js.sentry-cdn.com
    https://plausible.io;
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
  font-src https://fonts.gstatic.com;
  img-src 'self' https://images.unsplash.com data: blob:;
  connect-src 'self'
    https://peakly-api.duckdns.org
    https://api.open-meteo.com
    https://marine-api.open-meteo.com
    https://plausible.io
    https://wsoqcfwkvvemtlddcgfc.supabase.co
    https://o4511108649058304.ingest.us.sentry.io;
  frame-ancestors 'none';
">
```

Test: Babel inline eval works, Supabase magic-link redirect lands, Plausible fires. **Time: 25 min.**

## 9. What Breaks First at Scale

Same answer as every run, because the fix is the same command it's been for 20 days:

**Open-Meteo client-side calls.** The sequence:
1. Reddit/HN post → 300 concurrent users, all with cold caches
2. 300 × 250 = 75,000 Open-Meteo calls in ~3 minutes
3. Open-Meteo rate-limits the GitHub Pages shared IPs (you share ~50 IPs with thousands of sites)
4. `fetchWeather` returns HTTP 429/null for all 148 venues
5. `scoreVenue` gets no weather data → floors every score to 0 or `null`
6. Explore feed: 148 venues all showing "N/A — 0 score"
7. Users screenshot it and post "Peakly is broken" in the same thread that sent them there
8. You find out 2 hours later from a reply

The fix is deployed. It's in proxy.js. It has a 2hr in-memory cache + in-flight dedup: 148 venues = 148 upstream calls every 2 hours regardless of concurrent users. At 10K MAU that's still 148 calls/2hr. **One SSH command.**

Second break point at scale: in-memory rate-limiter Map in proxy.js (~lines 21–45). No persistent store — eviction every 5 minutes. At 10K MAU, the Map between sweeps holds 10K+ entries. On 1GB RAM this OOMs. Fix: $6/mo upgrade to 2GB before 10K MAU, 5 minutes in the DO console.
