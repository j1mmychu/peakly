## One Product Risk Nobody Is Talking About

**Magic-link-only auth will collide with App Review.** Apple reviewers test sign-in from a sterile environment and routinely reject or stall apps whose only auth path requires receiving an email mid-review (they often can't, or won't, wait for a magic link on a test account). Peakly has no password path and no demo mode. Before submission: write App Review notes that either (a) provide a reviewer-workable test path (e.g., a documented test account with a pre-arranged confirmation flow, in the spirit of the existing `ALERTS_TEST_ENABLED` review guard), or (b) state explicitly that sign-in is optional and the anon flow is the full product — which is true today, but it has to be *said* in the notes, or the reviewer sits at the magic-link screen and rejects. Zero code may be needed; the risk lives in the submission packet, not the app.
