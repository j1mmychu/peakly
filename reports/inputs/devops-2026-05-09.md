```

?? reports/inputs/pm-2026-05-08.md             (20648 bytes, written 16:10 UTC)
```

Plus three modified-but-uncommitted files from the same window:

```
M CLAUDE.md                                              (state-board updates)
M reports/known-skipped.md                               (entries appended)
M reports/ready-to-ship/pm-prompt-header-refresh-2026-05-06.diff (line-count refresh)
```

**Why:** `scripts/auto-push.sh` fires from Claude Code's PostToolUse hook on Edit/Write inside `~/peakly`. Scheduled-task agents (the routines that ran 05-08) execute outside that hook's catchment — their writes don't trigger the hook, so nothing commits. The contract that "everything in `reports/` is in git" is silently breaking each daily run.

**Two ways to close:**

A. **Lightweight (Jack does once/day):** add a `peakly-reports-sweep` cron on Jack's local box that runs once after the 17:30 daily-briefing slot:
   ```bash
   # crontab -e (Jack's machine, after 17:30 UTC briefing)
   45 17 * * * cd ~/peakly && bash scripts/auto-push.sh "daily reports + state notes" 2>&1 >> ~/peakly/scripts/.auto-push.log
   ```
   Picks up everything the day's agents wrote in one commit. No scheduled-task code change needed.

B. **Cleaner (one-time fix in the scheduled-task wrapper):** make each remote agent (devops/content-data/pm/revenue/ux) end its run with a `git -C <repo> add reports/ tasks/ && git -C <repo> commit -m "agent: <role> <date>" && git -C <repo> push` block. The local prompt files at `tasks/agents/*.md` would need a "## Final step — commit your output" section. Higher coordination cost (5 prompts to edit, race-condition risk if two agents push in the same window) but no Jack-machine dependency.

**Recommendation:** A first. The volume is low (5–10 small files/day) and cron sidesteps the race. Promote to B only if Jack misses a day and findings stack up.

**Time to apply (option A):** 2 min — one crontab line, one `mkdir -p scripts` if `.auto-push.log` doesn't exist.
