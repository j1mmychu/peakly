## Headline: two unreviewed architecture/feature changes shipped overnight via `auto:` commits

Since the last PM report (v57, `d603cca`, 06-13), the per-Edit auto-push pipeline shipped ~28 commits — **every one with an empty `auto: <files>` message, zero review, zero paper trail.** Two of them are not routine. They're the most consequential changes in the repo this week and nobody decided to make them:

### 1. A production BUILD STEP was added (`build-web.mjs` + esbuild + `deploy.yml`)

`scripts/build-web.mjs` (new) pre-transpiles + minifies `app.jsx` → `dist/app.min.js` with esbuild and rewrites `index.html` to drop Babel Standalone entirely. `deploy.yml` now runs `npm ci` + `node scripts/build-web.mjs` and ships **`dist/`** instead of the repo root. `esbuild ^0.28.1` added to devDependencies.

**Is this the right thing to build? Yes — the perf problem is real and launch-critical.** Babel-in-browser transpiling ~644 KB of `app.jsx` on first paint is genuinely 8–12s on mid-tier Android. For a mobile-heavy Reddit launch, that cold-load is a conversion killer, and pre-transpiling is the single biggest win available. The build is well-engineered: strict static-file allowlist (won't re-leak the business-plan PDFs), dev loop unchanged (local `index.html` still Babel-in-browser), fails loud if Babel leaks into `dist/`, keeps the cache stamp in lockstep.

**But it was shipped the wrong way:** it directly contradicts CLAUDE.md's most load-bearing constraint — "**No build step**" appears 3× including under "Do NOT Do: Do NOT add a build step or bundler" — and it landed with no commit message, no review, and no doc update, one week before launch, changing the production deploy mechanism. This is Open #14 (unreviewed auto-push) realized at architecture scale.

### 2. A Leaflet map feature was added (`ensureLeaflet()` lazy-load)

`app.jsx` grew ~775 lines (net +~400, only 1 line is stamp churn) — the substance is a Leaflet map integration: `ensureLeaflet()` promise-loader, `leafletReady` effect, two `PerformanceObserver` perf marks, new Leaflet CDN dep. It's lazy-loaded (cold-load cost contained), which is the right call. But a brand-new map feature + CDN dependency jumping the queue **during launch-hardening week** is scope creep, again with no decision behind it.
