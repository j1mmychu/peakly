## One Product Risk Nobody Is Talking About

**The auto-push pipeline gap has been quietly leaking for the entire last cycle, and we only noticed today because DevOps stared at `git status` long enough.**

The prior risk (05-08) was "auto-push velocity is faster than QA." Today's risk is the inverse: **auto-push velocity dropped to zero for scheduled-task agents, and nobody noticed for 24 hours.** The pipeline succeeded for the local-Claude-Code-edit catchment (which is where Jack's interactive sessions write) but silently failed for the scheduled-task catchment (where the agents write daily). The two are coexisting, and the failure mode is invisible: agents file findings, those findings become known-skipped per Rule 2 because the next agent reads them as "filed yesterday and not gone away," but the underlying file isn't actually in git for downstream consumers (briefing agent, future PM runs reading state).

The deeper issue: the findings-to-fix loop assumes durable writes. When writes are non-durable, the loop reports the same things repeatedly, the two-strikes rule fires (which it correctly did today via DevOps), findings move to `known-skipped.md`, and we lose visibility on real items because the rule was designed for "Jack has implicitly decided" not "Jack never read this."

The cron fix closes this immediately. But the meta-lesson is: any process built on agents writing files needs a durability check. If the auto-push hook hadn't fired for Jack's local edits either, we'd be operating completely blind. That's not the case today — Jack's local edits are committing fine — but it's a single-point-of-failure worth documenting. The reason this didn't blow up worse is that DevOps noticed in time. We need the same noticing-mechanism for any new agent-writes pipeline we add.

The systems analogue: this is the same class of issue as the `_alerts` Map persistence — both are "data sitting in memory waiting for someone to flush it to disk." Both are tolerable at <100 users. Both become real bugs the moment a real user depends on the data. The cron is the disk-flush for the agent-writes pipeline. Ship it.
