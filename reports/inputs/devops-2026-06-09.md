### P0-2 — Auto-push hook is hardcoded to one machine; agent writes silently never commit

`scripts/auto-push.sh:11` → `REPO=/Users/haydenb/peakly`. The hook only fires inside Jack's local Claude sessions on that exact path. **Every scheduled-task agent (devops/pm/content/revenue/ux) writes outside the hook's catchment, so its changes never get committed until Jack happens to make a local edit.** This is not theoretical — it's the direct cause of P0-1 (134 venues stranded) and it's why the cache stamp reads `20260608aaah` today (2026-06-09): the dirty `app.jsx` hasn't been committed, so the auto-bump never ran.

This is the same root cause behind Open #13 and Open #14 (the pipeline ships — or fails to ship — logic changes with no review, no diff, no paper trail). Two mitigations, both cheap:

1. **Cron backstop** (Open #11's documented fix) — guarantees agent writes land daily after the briefing slot:
   ```bash
   ( crontab -l 2>/dev/null; echo "45 17 * * * cd ~/peakly && bash scripts/auto-push.sh" ) | crontab -
   ```
2. **Invariant guard in auto-push** (Open #14) — refuse to commit `app.jsx` if a known revenue/structure invariant regresses. Minimum viable:
   ```bash
   # in scripts/auto-push.sh, before the commit:
   if [ "$(grep -c GEAR_ITEMS app.jsx)" -eq 0 ]; then
     echo "❌ auto-push BLOCKED: GEAR_ITEMS missing (revenue regression)"; exit 1
   fi
   ```

Est. time: 2 min (cron) + 10 min (guard).

## High (P1) — This week

### P1-1 — proxy.js CORS allow-list ships `localhost` origins to production

`server/proxy.js:27-28` → `ALLOWED_ORIGINS` includes `http://localhost:8000` and `http://localhost:3000`. Low real-world severity (an attacker can't make a victim's browser originate from localhost in a useful way), but it's sloppy for a prod allow-list and was flagged on 06-07. Gate it behind env rather than shipping dev origins:

```js
const ALLOWED_ORIGINS = [
  'https://j1mmychu.github.io',
  'https://peakly-api.duckdns.org',
  ...(process.env.NODE_ENV !== 'production'
      ? ['http://localhost:8000', 'http://localhost:3000'] : []),
];
```

Rides with the parked VPS redeploy (it's a proxy.js change), so no extra deploy cost — fold it in when the redeploy finally happens. Est. time: 2 min.
