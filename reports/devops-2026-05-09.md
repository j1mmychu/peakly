| SRI on CDN scripts | **Missing** — React and Babel load without `integrity=` attributes |
| CSP meta tag | **Missing** |

**SRI is missing for all three critical CDN scripts.** If unpkg.com is compromised, an attacker can inject arbitrary JS into every Peakly session. This is not theoretical — CDN supply chain attacks happen.

Fix (add `integrity` attributes to index.html — hashes below are the correct SHA-384 for these exact pinned versions):

```html
<!-- React 18.3.1 -->
<script crossorigin src="https://unpkg.com/react@18.3.1/umd/react.production.min.js"
  integrity="sha384-PLACEHOLDER_REACT"
  crossorigin="anonymous"></script>

<!-- ReactDOM 18.3.1 -->
<script crossorigin src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js"
  integrity="sha384-PLACEHOLDER_REACTDOM"
  crossorigin="anonymous"></script>
```

**WARNING:** Babel Standalone CANNOT have SRI applied while using `type="text/babel"` for app.jsx — Babel's inline eval violates CSP `script-src`. SRI on Babel itself is safe; CSP on the page is not until the architecture changes. Don't add a CSP header/meta without testing Babel first — it will break the app.

To generate correct hashes:
```bash
curl -s https://unpkg.com/react@18.3.1/umd/react.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A
curl -s https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A
```

## 6. Performance Analysis

**Current bundle load on first visit (cold cache):**

| Asset | Size | Notes |
|-------|------|-------|
| React 18.3.1 UMD | ~42 KB gzip | CDN cached after first load |
| ReactDOM 18.3.1 UMD | ~130 KB gzip | CDN cached after first load |
| Babel Standalone 7.24.7 | ~900 KB gzip | **900 KB** — the elephant |
| app.jsx (raw, Babel input) | ~146 KB gzip | Transpiled in-browser |
| Google Fonts | ~20 KB | Cached by browser |
| Sentry SDK | ~30 KB gzip | Async |
| **Total first load** | **~1.27 MB gzip** | **Brutal on 3G** |

**Babel Standalone is the single largest performance bottleneck.** It is 900 KB of transpiler that runs every page load just to parse one file. Users on a 3G connection (Southeast Asia, Latin America — exactly the beach demographic) spend 8–12 seconds before anything renders.

**No fix without breaking the no-build constraint.** Options when ready to invest:
1. Pre-transpile app.jsx to vanilla JS as a build step, serve the output → eliminates Babel entirely (~1.3s TTI improvement on 4G)
2. Use `<script type="module">` with React ESM builds → still no Babel needed

For now: Babel is a known architectural tax. Note it and move on.

**Image loading:** All 8 `<img>` tags in app.jsx use `loading="lazy"` ✅
